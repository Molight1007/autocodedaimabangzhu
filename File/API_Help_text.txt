**什么是自治修复？**

自治修复模式下，AI 将自动进行多轮代码生成、测试、修复的闭环迭代，无需用户手动干预，直到代码通过测试或达到最大尝试次数。

**工作流程：**

1. AI 分析题目并生成初始代码
2. 自动运行测试用例验证
3. 若未通过，自动分析错误并修复
4. 重复步骤 2-3，直到通过或达到上限

**注意事项：**

- 自治修复可能会自主进行多轮对话，会产生额外的 Token 消耗
- 默认最多尝试 15 轮，可在配置中调整
- 最终返回通过测试的代码，或最后一次修复结果

**特别注意：** 自治修复暂时仅解题可用，出题模式下，即使选择了也是按默认的普通请求

### **什么是双算法对拍验证？**

双算法对拍验证是一种更严格的代码正确性检查机制。它会同时生成两份**算法思路不同**的代码（例如一份暴力枚举、一份动态规划），在相同测试数据上运行并比对输出是否一致。

**适用场景：**

- 题目存在多种解法（如暴力、贪心、动态规划）。
- 你希望获得更高置信度的答案，愿意付出额外 Token 和时间成本。

**工作流程：**

1. 分析题目，判断是否可构造两种不同算法。
2. 并发启动两个独立的 AI 会话，分别按指定算法生成代码。
3. 两份代码在全部测试数据上运行，比对输出是否完全一致。
4. 若不一致，将差异信息反馈给两个 AI 进行一次交叉修复，然后重新对拍。
5. 最终返回通过验证的代码（优先推荐优化版本），或降级返回单 Agent 结果。

**注意事项：**

- 该功能**默认关闭**，需在界面上手动点击“双算法验证”按钮启用。
- 由于需要并发运行两个 Agent，Token 消耗约为普通自治修复的 **2～3 倍**。
- 若题目无法构造两种异构算法（如输出不唯一、只有一种解法），系统会自动降级为普通自治修复，并给出提示。
- 暴力算法在小数据上运行，若数据过大可能跳过对拍，但不影响优化代码的最终输出。

**与普通自治修复的区别：**

| 功能 | 普通自治修复 | 双算法对拍验证 |
|------|-------------|---------------|
| Agent 数量 | 1 个 | 2 个（并发隔离） |
| 验证方式 | 仅运行样例和自测稳定性 | 两份异构代码交叉比对输出 |
| 正确性置信度 | 中等（依赖样例覆盖） | 高（自洽性验证） |
| Token 消耗 | 基准 | 约 2～3 倍 |
| 适用题型 | 所有 | 输出唯一、存在多解法的题目 |
